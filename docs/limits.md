# What we can't do yet — the honest limits

This is the single place where every known limit of the tool is written down in plain
words. It is **the source of truth**: the QA report published on every CI run embeds
the table below verbatim, so a limit recorded here reaches every reader automatically
and a limit *not* recorded here is invisible — which is exactly why it belongs here
first.

The rule behind it: **we never claim a file is untraceable unless we have actually
proven it.** Where a limit is a law of physics, we say so instead of pretending it is
solved. Where our own claim turned out to be broader than our evidence, we write that
down too, rather than quietly narrowing it.

Status key: ✅ solved · 🟡 bounded (small, measured, documented) · 🔴 open (known gap,
not yet fixed) · ⚪ out of scope (impossible, or outside the threat model) ·
🔜 planned.

| **1** | Even after every tag is deleted, the *way* a file was compressed leaves a hidden signature that can hint which app, phone or program made it. | We re-save through **one standard encoder** so every file we produce shares the same signature. What leaked in the meantime was approximately "made by Word 2010-or-later", never who wrote it. | ✅ **Solved at the deep clean** |

What cannot be recovered afterwards is the review history — so a document you still need to review should be cleaned at the light level, or reviewed first. | 🟡 **Bounded trade-off** |

Which parts a program emits, which styles it defines, what settings it records and how it builds a paragraph all differ between Word, LibreOffice and everything else. | **Measured across four producers, not assumed.** The deep clean closes exactly half of it — the *spelling* of the markup (namespace names, tag style, punctuation of the header line) is rewritten through one writer and stops separating anyone. | **26** | **The strongest Word clean re-types the document through a different program**, so fonts can substitute and spacing can shift. It is the only level that does not preserve the page exactly. | **The trade is stated before the level is offered.** It exists because the previous level cannot remove what a program's *choices* say about it — which styles it defines, which settings it records — and only rebuilding the document through one program can. **We cannot currently measure the cost**, and say so rather than claiming there is none: our check renders the document through the same program that rebuilt it, which is that program grading its own homework. | **27** | **Even after rebuilding a Word document through one program, a trace of how the *original* was made survives** — the styles the source defined are carried through rather than rebuilt. | **Measured, and narrowed to a single clue.** The rebuild collapses almost everything: which parts exist, which settings are written, how paragraphs are built all become the rebuilding program's, identically, for every file. What is left is one list, and it describes the document's **origin**, not the program that handed us the file. It is the same kind of leftover as a re-recorded audio file remembering its first recording's quality setting. | 🔴 **Open — narrowed to one clue** |
| **28** | **The report printed after each clean shows only what *this tool* can see**, and it prints the very values it removed. | Two things stated rather than assumed. First, "nothing listed" means *we found nothing*, never *the file was clean* — a hiding place no format handler models is missing from the report for the same reason it is missing from the clean. That is why every report now ends with a reading by **ExifTool, a different program**, including the exact command to repeat it yourself: our own account of our own work is not evidence, and where the two disagree the report says so and tells you to treat the clean as incomplete. Second, the report is a disclosure: an author's name and a GPS position that were inside a file end up on the terminal, and in the log if the output is redirected. Values are shortened, `--no-verify` skips the second opinion, and `--no-report` turns it all off. | 🟡 **Useful, with both edges named** |
| **29** | **Cleaning an already-cleaned file is free at the light levels and costs quality at the strongest one.** Running the deep clean twice re-records the file a second time. | **Measured, and the two halves behave differently on purpose.** Every bit-preserving and lossless level is a **fixed point**: clean a cleaned file and you get the identical file back, byte for byte, on all seven formats — which is also the proof that the first pass left nothing behind for a second one to find. The strongest level re-encodes, so a second pass is a second generation of loss, exactly as re-saving a photo twice would be. **Clean once, from the original.** A pipeline that cleans a file at each of several stages is quietly degrading it. | 🟡 **Fixed point where it matters; stated where it isn't** |

## Where the evidence lives

<!-- RESIDUALS:BEGIN -->
- **How these verdicts are decided:** a one-sided binomial test against chance (alpha 0.10), not a fixed accuracy margin. The margin came first and was wrong: on 18 trials the standard error is ~0.12, so it turned sampling noise into a verdict and the same experiment landed on opposite sides on macOS and Linux. Every peer set now runs 36 trials per condition and reports its p-value.
- **DQT (JPEG quantization tables):** the F1/F2 fingerprint source — neutralised at F3 via a single standard encoder.
- **LAME/Xing header + bitrate contour (MP3):** the audio equivalent — survives F1, normalised at F3.
- **FLAC block size, framing and vendor string:** survive F1, normalised at F2 with **bit-identical audio** (STREAMINFO's MD5 of the unencoded samples proves it). The vendor string ("reference libFLAC…", "Lavf…") names the encoder outright but sits in a metadata block, so unlike MP3's LAME tag it costs nothing to remove. FLAC and PNG are the two formats where A2 is free.
- **Our own canonical form:** a scrubbed FLAC carries exactly one metadata block, so `fLaC` + the STREAMINFO header is constant across outputs; the MP3 canonical LAME header is the same kind of constant. Recorded in each matrix's `excluded` block and as limit #9 — it marks a file as scrubbed, never as scrubbed-from-what. Two earlier candidates were removed rather than excused after the fingerprint guard caught them: a fixed empty Vorbis comment and 8 KiB of fixed zero padding.
- **Cross-engine audio trace (MP3):** measured, not assumed. A classifier that identifies the source encoder from the sound alone scores **0.89 on untouched and F1 files and 0.53 after F3** (p=0.43, n=36 — not significantly above chance). Peer set includes `shineenc`, an encoder that is not libmp3lame. Scope: frequency-profile features; MDCT-domain classifiers untested (limit #6).
- **Anonymity groups (MP3 F3):** the standard 192 kbps setting is illegal for MPEG-2 sample rates, so those files emit at 160 kbps instead — separate groups (limit #2). Producer-anonymity is verified **within each group**, in header space (E-LAME, both rates pass) and in audio space (E-ENGINE: 44.1 kHz 0.89 → 0.53 at p=0.43, 22.05 kHz 0.94 → 0.58 at p=0.20, n=36 per group, chance 0.50). The group boundary follows the source's sample rate, which is content, not a producer trait.
- **M4A audio-space residual (E-M4A-AUDIO):** the source's own quality setting is recoverable from the sound at **0.88 on unscrubbed and copy-tier files, falling to chance (0.50) after F3**; same-source producers become byte-identical. Engine identity (ffmpeg AAC vs Apple AAC) is **not separable even unscrubbed** (0.56) — those two encoders are near-twins spectrally (99.5%-energy bandwidth 15075 vs 15427 Hz at the same bitrate), so this corpus cannot answer the engine question either way, and says so rather than counting a weak control as a pass (limits #10, #12).
- **Perceptual gate, two-stage:** AAC rebuilds noise rather than copying it, so waveform correlation alone refuses legitimate scrubs — measured 0.86-0.90 on noise through AAC versus 0.998 for MP3 on the same material. The gate now requires strong waveform correlation OR (still-strong correlation AND a matching time-frequency energy envelope). Both parts are needed: envelopes alone accept two different noise recordings, waveforms alone reject good AAC (limit #11).
- **PRNU (sensor noise) / microphone + room response / mains hum:** structural impossibilities; documented, out of scope (limit #5).
- **M4A muxer layout vs coded audio:** two producers in one file. F2 normalises the layout (box order, brand, `free` slack) losslessly; F3 additionally collapses same-source producers to byte-identical output. The primary-encoding trace from a differently-encoded original survives both, and is recorded as an open residual (limit #10) because no audio-space classifier has been run for M4A yet — the MP3 E-ENGINE treatment is what would settle it.
- **Primary-quantization estimate:** the bounded "was re-saved" hint after F3 — reveals nothing about original metadata.
- **PDF incremental-update history:** the format's own edit mechanism is *append*, so every earlier draft stays in the file and opens as a document if you truncate at an earlier end-marker. Closed by rebuilding the file from the object graph rather than appending — measured (E-PDF-HISTORY) with three independent attacks: revision rollback, raw carving, and an object ledger that separates *superseded* definitions from *orphaned* ones. A plain rewrite that strips nothing already recovers nothing, so the rewrite and the scrub are measured separately and neither takes credit for the other.
- **PDF producer channels, split in two:** the **serializer** (object order and numbering, xref style, the binary header comment, `/ID`, `/Length` conventions) and the **layout engine** (content-stream operators, number precision, font subsets, glyph geometry). F1 normalises the first by writing the bytes itself; the second is untouched at F1 and only partly normalisable at all — glyph positions and subset composition cannot change without re-typesetting the page. Reported as two named key groups so a cell never averages them.
- **PDF font and ICC internals (limit #14):** embedded font programs keep `name`/`OS/2`/`head` (foundry, copyright, build date — measured `head.created` intact on a scrubbed LibreOffice document) and ICC profiles keep their descriptive tags. Header fields are already zeroed by `standards/icc.py`; the tag data is not, because rewriting it changes colour rendering.
- **PDF producer channels, measured (E-PDF, five producers, one document):** at `raw` all three channels identify the producer; after F1 the **serializer channel is closed outright** (header, binary comment, xref kind, object streams, trailer keys, indirect `/Length` — none of them separate producers any more) while the **layout channel is untouched** (operators, number precision, font subsets, glyph digest, stream count) and **size** still leaks. So A2@F1 fails on the layout engine alone, which is what F2 is scoped from. Per W5, only part of that is normalisable without re-typesetting: `struct:glyph_digest` is the predicted floor, and a test asserts it is leaking today so an F2 that passes by breaking the measurement cannot slip through.
- **Our own PDF canonical form:** every output is `%PDF-1.7` with no binary header comment, no `/ID`, catalog as object 1, sorted dictionary keys and one classic xref table. PDF's mandatory skeleton is interleaved through the whole file rather than being a short prologue, so `mandatory_constants()` declares **the empty document our writer emits**, generated not transcribed — a run common to every output that is a substring of a document with *no content* is structure by construction. The declaration is broad, so it is checked rather than trusted: the skeleton must contain no producer string, no timestamp and no padding run. Limit #9 again — it marks a file as canonically rewritten, never as rewritten from what.
- **PDF F2, measured (E-PDF, same five producers):** F2 rewrites every content stream through one writer — number spelling, `Td`/`TD`/`T*` folded into the absolute `Tm` they amount to, show runs merged into one `TJ`, one compression filter, canonical font subset tags, one content stream per page. That **closes the text machine's spelling**: four of the five producers come out with an identical text-operator vocabulary, and the two synthetics that differed only in how they wrote the same page become indistinguishable on it. **A2@F2 still fails**, and what survives is substance rather than style: glyph positions and advances, which font the engine chose, how many objects it embeds, its graphics-operator vocabulary, and file size. Named per key rather than as "the layout channel", because the channel verdict alone would read the same whether F2 had collapsed most of it or none of it.
- **PDF glyph geometry is the F2 floor:** where each glyph sits, how far it advances, where lines break, and which glyphs are in the subset. None of it can change without re-typesetting the page, which would change what the reader sees. Same species as PRNU: document it, do not pretend it is a bug awaiting a fix. F3 (rasterise) moves it into pixel space rather than removing it.
- **PDF character spacing is content, not spelling:** one peer producer (macOS Quartz) genuinely sets `Tc`, so its text-operator vocabulary still differs after F2. Dropping the operator would make the cell pass and change the rendering, which is the wrong trade — the leak stays and is named.
- **PDF F2 coordinates are quantised to 1E-8 user-space units.** Composing a relative move into an absolute matrix can grow the digit count without bound, so emitted coordinates are rounded there. That is 1.7e-7 of a pixel at 1200 DPI — far below anything that can change a rendered dot, and rendered output is byte-identical across all five producers at 150 DPI — but it is a real value change and F2 is described as lossless to well below a rendered dot rather than as bit-exact in the numbers.
- **PDF filters we deliberately do not normalise:** `/DCTDecode` and `/JPXDecode` are lossy, so re-encoding them would be an F3 operation wearing an F2 label; `/JBIG2Decode` and `/CCITTFaxDecode` are lossless but re-encoding a scanned page to Flate multiplies its size. Filter choice therefore survives on those streams.
- **PDF embedded font programs keep their internal subset name.** F2 reassigns the six-letter tag on `/BaseFont` and `/FontName`, but a CFF `FontFile3` carries its own name index and rewriting that means re-emitting the font. Readers use the PDF dictionary, so rendering is unaffected — the original tag survives inside the font program.
- **Our PDF deflate level is 6, and that is measured rather than picked.** The zlib header gives the level away (`78 9C` = 6, `78 DA` = 9). Level 9 was the first choice, copied from PNG F2, and the fingerprint guard failed immediately with ` >>\nstream\nx\xda` as our signature: across the peer corpus four of five producers emit level 6 and one emits level 1, and **none** emits 9 — so level 9 did not normalise our output, it labelled it. Level 6 joins the largest crowd that actually exists.
- **PDF F3 destroys the text layer, and that is the tier's real cost.** Rasterising preserves what the reader *sees* — the page is a picture of itself — but a scrubbed file can no longer be searched, selected, copied from, or read by a screen reader. That is an accessibility regression, not a compression artefact, and it is stated before the tier is offered rather than after it is used. F3 also rounds page dimensions up to the render pixel grid (at most 0.48 pt at 150 DPI).
- **PDF F3 does NOT defeat A2, measured (E-PDF-RASTER).** Structurally F3 passes almost trivially — the file is entirely our own output — and publishing *that* as the verdict would have been the overclaim this project exists to avoid. Attacking the **rendered pixels** instead: a leave-one-document-out nearest-neighbour classifier over ink geometry identifies the producer on **100% of pages (n=30, five producers, chance 0.20, p<0.0001)** after F3, against a valid control of 100% on unscrubbed pages. The typesetter's geometry is painted into the image; rasterising relocates the residual, it does not remove it.
- **The DPI knob is not a Pareto trade, and the reason corrected our own prediction.** The plan expected lower resolution might blur the signal, on the assumption it lived in *sub-pixel* glyph placement. It does not. Swept from 300 DPI down to **18 DPI — where the body text is unreadable — the classifier stays at 100%**. An ablation says why: the **ink-density scalar alone sits at chance** (0.17), so the attack is not reading page size or darkness, while the **column profile alone reaches 100%** — left margin, right edge and horizontal extent of the text block. That is coarse-scale layout geometry, which downsampling leaves entirely intact. Holding page size constant (Letter-only producers) changes nothing. There is no resolution at which the document is still useful and the typesetter is anonymous.
- **Redaction is not metadata scrubbing, and we do not do it.** Text hidden under a black rectangle is a drawing operation with the words still underneath; every tier preserves content, so the scrub preserves the hidden text exactly as faithfully as the visible text — a test asserts this stays true. The tool **warns and never fixes**: it reports invisible text (rendering mode 3/7), text outside the crop box, and text drawn under an opaque fill that covers it. The warning is advisory and never fails the scrub. It deliberately **under-reports**: "text under an opaque fill" in full generality needs blend modes, transparency groups and z-order — a small renderer — so a rotated fill, a fill in a different stream, or any page using a named graphics state is not reported. An empty warning list means "none of these three patterns", never "safely redacted".
- **PDF F2 makes files bigger, and size is itself a leak channel.** Measured on a real 10-page Chrome-printed report: 448 KB in, 452 KB at F1, **590 KB at F2** (+32%), 3.9 MB at F3. F2 grows because every stream is decompressed and re-deflated with no predictor, and because absolute `Tm` positioning is more verbose than the relative `Td` chain a producer emits. `struct:size` is a channel we already report as leaking, so this is a real cost rather than a cosmetic one.
- **Scrubber-fingerprint guard:** confirms our *own* tool leaves no producer/creator string, no odd padding, deterministic ordering, and no modification-time stamping.
- **DOCX package conventions, measured across five producers (E-DOCX-ZIP):** create-system byte, `version made by`, general-purpose flags, extra fields, external attributes, entry order and the timestamp *scheme* all separate producers before a single tag is read. Word writes the ZIP epoch `1980-01-01`, LibreOffice and macOS `textutil` write local wall clock. **Word's deflate is not zlib** — no level reproduces any of its entries, and it declares `super-fast` in flag bits nothing else sets — so matching Word's compressed bytes is not achievable in any language; our writer joins the zlib crowd at **level 6**, which is where LibreOffice, textutil and MAT2 all sit. Compression level is *recovered* by recompression rather than read, because ZIP stores raw deflate with no zlib header byte, and the honest unit is an equivalence class per entry intersected across the package — a first-match search reported three different levels inside one producer.
- **Our own DOCX canonical form:** every output has `[Content_Types].xml` first then parts sorted, `create_system` 0, versions 20, flag word 0, the 1980 timestamp, deflate level 6, `external_attr` 0, and no extra fields, archive comment or directory entries. Limit #9 again — it marks a file as canonically repackaged, never as repackaged from what. The stdlib could not produce it: CPython overrides `external_attr = 0`, the one value Word, LibreOffice and textutil all write, putting the operator's umask in every entry.
- **The DOCX session-ID family (E-DOCX-LOCI, and the E-SESSION-ID target):** `w:rsid*` attributes, the `w:rsids` pool, a standalone `<w:rsid>` inside every `w:style`, `w14:paraId`/`w14:textId` per paragraph, and `w14:docId`/`w15:docId` per document. MAT2 0.14.0 clears the RSIDs and **leaves the rest**, which contradicts the inherited claim that RSIDs survive every scrubber — measured on our corpus rather than repeated from the literature, and not published as a result until E-SESSION-ID runs it with controls. `w14:paraId` is the sharpest of them: it travels with a paragraph pasted into another document, so it links *files to each other*, an attack the A1/A2/A3 ladder does not model.
- **DOCX residuals F1 knowingly leaves:** bookmark names other than `_GoBack` (link targets — limit #20), external relationship targets (removing one breaks a visible link), `word/fontTable.xml` (a weak machine-profile hint), and the versioned namespace declarations that date the producing Word (limit #21). All reported by `residuals()`, never silently dropped.
- **The inherited RSID claim is false, measured (E-SESSION-ID):** MAT2 0.14.0 clears `w:rsid*`, the `w:rsids` pool and the per-style `<w:rsid>`; it **leaves** `w14:paraId`/`w14:textId` (one per paragraph, and they travel with a pasted paragraph, so they link files to each other rather than a file to a producer) and `w14:docId`/`w15:docId` (a persistent per-document GUID, in two namespaces). Our F1 clears all six, on a synthetic corpus and on a real Word document. **ExifTool cannot write DOCX at all** (`Can't write DOCX files`) — a capability gap, reported separately from a failure, because a tool that declines leaves the file untouched while a tool that writes a still-dirty output has misinformed its user.
- **DOCX producer channels, split in two (E-DOCX, four producers, one document):** the **packager** (create-system, external attributes, flag bits, entry-ordering policy, timestamp scheme) and the **document model** (XML declaration spelling, self-closing style, namespace set, part set, style ids, settings keys, `sectPr` defaults, paragraph idiom). At `raw` both channels plus size identify the producer; after **F1 the packager channel is closed outright** while the model channel is untouched, because F1 edits the XML only by deletion. That scopes F2 to one channel from a measurement rather than a guess — and splits it further: `xml_decl`/`selfclose_style` are spelling and should collapse, while `entry_set`/`style_ids`/`paragraph_idiom` are substance and are the candidate floor.
- **Three DOCX A2 features were measuring the wrong thing and were corrected before publication:** the recovered deflate *level class* reported **part size** (it narrows as a part grows, so tiny parts matched levels 5-9 and larger ones matched only 6, though all were written at 6); the raw *entry order* stopped measuring ordering once our writer sorted, becoming a function of which parts exist; and *entry set* was filed under the packager when it is the document program's decision. Without the fixes the published cell would have claimed a packager leak on the strength of a size artifact and a misfiled key.
- **`docProps/thumbnail.jpeg` is dropped whole, not cleaned in place:** it is a rendered page image carrying its own EXIF, it can be **stale** (showing content the document no longer displays — the DOCX relative of PDF revision history), and being a rendering it carries the typesetter's geometry in pixel space, the residual E-PDF-RASTER measured at 100% producer identification. MAT2 strips its EXIF and keeps the picture.
- **DOCX F2 closes spelling and not substance (E-DOCX, four producers, one document):** canonical re-serialisation through one writer closes `xml_decl`, `selfclose_style` and `namespaces` — and the last of those closes limit #21, since an unused versioned-namespace declaration is dropped along with its `mc:Ignorable` entry once F1 has removed the last user. What survives is `entry_set`, `style_ids`, `settings_keys`, `paragraph_idiom`, `sectpr`, `part_types` and `has_theme`: which parts a producer emits, which styles it defines, what it records in `settings.xml`, how it builds a paragraph. None of it can change without changing what the reader sees. Reported per key rather than as a channel verdict, because a channel verdict alone would read the same whether F2 had collapsed most of it or none of it.
- **DOCX F2's canonicaliser had to preserve default namespaces**, and the reason is worth recording: rewriting `<Types xmlns="…">` as `<ct:Types xmlns:ct="…">` is namespace-equivalent XML that **every real OPC reader rejects** — LibreOffice refused all five producers' output. Caught only because the acceptance test is *does it still open*, not *did we write a file*. Whether a part uses a default namespace is decided by the part type, not the producer, so preserving it preserves no fingerprint.
- **Our own DOCX canonical form (F2):** the `mandatory_constants()` declaration includes **our own output for a document with no content**, generated rather than transcribed, because the guard failed the moment F2 landed and reported the complete `_rels/.rels` entry as our signature. That is real convergence rather than a corpus artefact — every package's root relationships part declares exactly one relationship once `docProps/*` is dropped, so canonicalisation gives them all the same bytes. Limit #9 again: it marks a file as canonically rewritten, never as rewritten from what. A test asserts the declared skeleton carries no locus at all, so the broad declaration cannot hide a real leak.
- **DOCX content preservation is checked in pixel space, not only against our own invariant:** each document is rendered through LibreOffice before and after F2 and the images compared. All four real producers render byte-identically. The text-only check was additionally found to be *unsound* on F2 output — a regex extractor treats a canonical `<w:t/>` as an opening tag and swallows the markup up to the next run — so the oracle now parses instead of matching.
- **DOCX F3 collapses the model channel to one key (E-DOCX at F3):** a re-typeset through one engine regenerates the document model rather than relocating it, so `entry_set`, `settings_keys`, `paragraph_idiom`, `sectpr`, `part_types` and `has_theme` all stop separating producers. What survives is `style_ids`, and it is a **primary-production trace** — the engine preserves the *source's* styles rather than rebuilding them from nothing — the same species as M4A's primary-encoding trace. This is the one tier in the project where F3 buys what F2 could not, and the reason is structural: PDF F3 photographs the typesetter's geometry into pixels (E-PDF-RASTER: 100% producer identification), while a DOCX round-trip rebuilds the symbolic model.
- **DOCX F3's rendering cost cannot be measured with the tools on hand, and is reported as unmeasured rather than zero.** Rendering before and after through LibreOffice returns identical images — but LibreOffice is also the engine that performed the round-trip, so the check is the engine grading its own homework. The real cost appears on opening a re-typeset Word document *in Word*, which cannot be scripted on any platform (the same wall the DOCX peer set hits). A test asserts the identical hashes precisely so they are not mistaken for evidence of losslessness.
- **Idempotence, measured across every format:** `scrub(scrub(x)) == scrub(x)` byte for byte at **every F1 and F2 tier** (JPEG, PNG, PDF, DOCX, MP3, FLAC, M4A). That is the strongest available statement that a canonical form really is canonical — a second pass finding anything to change would mean the first left an input-dependent trace, which is what the A2 defense claims it does not do. **F3 is deliberately not a fixed point** on any format, because a lossy re-encode run twice is a second generation; asserted rather than left as folklore, so nobody later "fixes" it (limit #29).

looking for proves nothing. E-PDF-RASTER additionally **ablates** its own feature
vector, because a classifier at 100% shows the producer is identifiable without
showing what from — and "glyph geometry survives" would have been an interpretation
laid over a number that could equally have come from page size.
