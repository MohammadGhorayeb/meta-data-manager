# CLAUDE.md — Irreversible Metadata Scrubber

Persistent context for Claude Code, read at the start of every session. Keep this file lean; depth lives in `docs/` (linked below). When something here would otherwise be re-explained every session, it belongs here; when it's a long procedure or detail, it belongs in `docs/`.

## What this project is
A tool that **irreversibly strips metadata from files of arbitrary type**, for privacy/anonymization. University implementation project: a research phase plus an implementation phase, structured as a 10-step plan. **The deliverable is a working tool, not a paper** — research only matters insofar as it informs the build. A parallel deliverable is a professional funding proposal (technical content + cost plan).

## Core definition (do not drift from this)
- **"Irreversible" = forensic unrecoverability from the scrubbed file itself**, not mere field deletion.
- **Threat model is medium-tier (adversary A2):** a journalist or amateur investigator using off-the-shelf forensic tools. Not a nation-state.
- The original file persisting on disk is a **workflow** concern, not a property of the scrubbed file.

## Hard constraints (every format)
1. **Content preservation** — file stays functional and perceptually identical (same pixels / waveform / visible text / runtime behavior).
2. **Irrecoverability beyond deletion** — handle redundant copies (EXIF + XMP + IPTC + ICC), embedded thumbnails/previews, side-channel leaks (file size, structural fingerprints, encoder signatures), and the scrubber's own fingerprint.
3. **All three operating depths are in scope** — high-level libraries, format-spec parsing, raw binary/hex (magic numbers, offsets, integrity-field recomputation).

## Framework (full detail in `docs/framework.md`)
- **Fidelity tiers:** F1 bit-preserving · F2 lossless re-encode · F3 lossy re-encode.
- **Adversary tiers:** A1 no-reference · A2 peer-corpus structural fingerprinting · A3 original-copy differential.
- **Feasibility is a Pareto/achievability matrix per format** (which A×F combinations are reachable) — **never a binary claim**, and requires empirical validation across all duplicate loci before it is stated as fact.
- **Verification primitive = differential testing:** two files, identical content, different metadata → scrub both → any non-noise diff is a leak. Use an n-way same-source set to test A2.

## Build approach (full detail in `docs/implementation_plan.md`)
- **Depth-first by dependency, not by popularity.** Format families are recursive containers, so build **leaves before containers**.
- **Phase 0 first (the spine):** differential-testing harness + test corpus + shared standard modules (EXIF/TIFF-IFD, XMP, ICC, ID3) + scrubber-fingerprint guard + magic-number dispatch skeleton. Build this before any single format.
- Then: P1 images (JPEG → PNG) → P2 audio (MP3) → P3 documents (PDF → OOXML) → P4 media/camera (MP4 → HEIC → RAW) → P5 executables → P6 tail + integration.
- Shared modules are written **once** and called by every format handler — never copy-pasted per format, because a missed copy is a leak.

## Definition of "done" for any format
1. Differential test passes at the claimed (A,F) point across **all known loci** (including embedded thumbnail/preview), not just named tags.
2. Residuals are **documented** in the Pareto matrix (e.g. DQT / PRNU / Lame / RSID), never silently ignored.
3. Scrubber-fingerprint guard passes on the output: no producer/creator string, normalized padding, deterministic standard-conformant ordering, no mtime stamping.

## Known conclusions (don't re-derive these)
- No surveyed tool achieves A2 resistance at F2 for any Tier-1 format; A2 without F3 re-encode is an open problem.
- JPEG A2-resistance generally requires F3 — in-place DQT quantization tables reveal the encoder (Kornblum).
- **OOXML RSIDs do NOT survive MAT2 — the inherited claim (Müller) is false against 0.14.0, measured (E-SESSION-ID, docs/p3_documents_plan.md §2.13).** MAT2 clears `w:rsid*`, the `w:rsids` pool and the per-style `<w:rsid>`, and **leaves** `w14:paraId`/`w14:textId` (per paragraph, and they travel with a paragraph pasted into another document, so they link files to each other) and `w14:docId`/`w15:docId` (a persistent per-document GUID). Our F1 clears all six. ExifTool cannot write DOCX at all. Don't repeat the RSID claim; the useful version is that a scrubber can close the named channel and leave the unnamed one.
- The Lame tag in MP3 audio frames can't be removed without re-encoding.
- MP3 A2 is closed at F3 **across engines, per sample-rate group**, measured twice: E-LAME (header space — producers collapse to one canonical signature; both 44.1 and 22.05 kHz pass separately) and E-ENGINE (audio space — engine classification 0.89→0.53 (p=0.43) at 44.1 kHz, 0.94→0.58 (p=0.20) at 22.05 kHz, chance 0.50, n=36 — verdicts are one-sided binomial vs chance, NOT a fixed accuracy margin (a margin turned noise into a verdict and disagreed macOS vs Linux)). Peer set includes `shineenc`, a non-libmp3lame engine. The grouping is deliberate: 192 kbps CBR is illegal for MPEG-2 rates so those emit at 160, and the source sample rate is content we preserve — never resample to collapse groups. Untested scope: MDCT-domain classifiers. Don't re-run these to re-establish the result; extend them.
- PDF has no published tool achieving A2 at F2.
- PRNU sensor noise survives F1/F2 and no metadata pipeline can remove it (Lukáš) — a structural impossibility; document it as such rather than treating it as a bug.
- **M4A carries two producers** — the muxer (box order/brand/`free` slack) and the AAC encoder (coded audio) — so its A2 cells name which channel leaked instead of averaging them. F2 normalizes the muxer losslessly (stream copy); F3 collapses same-source producers to byte-identical output; E-M4A-AUDIO then measured the audio side (source quality setting 0.88 unscrubbed -> chance after F3), so the only surviving channel is FILE SIZE (~1.4%, from a differently-encoded original). The coded-audio DIGEST is deliberately NOT in M4A's categorical A2 channel — having it there made M4A the only format judged on its own compressed content while MP3's channel is headers-only. ISOBMFF box walking lives in `standards/isobmff.py` — Phase 4's MP4/HEIC reuse it. The trap it exists for: `stco`/`co64` hold ABSOLUTE offsets, so removing any box before `mdat` requires patching them or the file decodes to garbage while still parsing.
- **iPhone video is QuickTime (`qt  `), not MP4, and keeps a stale second copy of its metadata inside `mdat`** where no sample table points — measured, M7 (`docs/p4_media_plan.md` §5): exact GPS in 6 of 6 clips (in `mdat` every 10 s of recording; clips under 10 s put it in a trailing top-level `free` box instead), device/OS/date in every Mac capture. `exiftool -all=` leaves it and reads its own output as GPS-free; MAT2 refuses `.mov` and crashes on a renamed one (ffmpeg cannot copy the `apac` spatial-audio track). So MP4/MOV F1 rebuilds `mdat` from the kept sample tables (per-chunk remap), never copies it, and its A1 check works on bytes, not ExifTool. QuickTime `meta` is a plain container; ISO `meta` is a full box — the walker must decide per box from the bytes. **MP4 A2@F1 fails, measured (E-MP4, 4 producers incl. an AVFoundation re-mux):** 5 of 9 muxer features close, `brand`/`compatible_brands`/`top_level_order`/`moov_before_mdat` survive — that list plus renumbering track IDs (`next_track_ID` still counts dropped tracks) is the F2 spec. MP4 was built twice (a parallel ISO-only branch, merged 2026-10-04, `docs/p4_media_plan.md` §8–§9); the QuickTime/rebuild handler won.
- **Camera RAW (survey M15, `docs/p4_media_plan.md` §7): the maker note cannot be dropped** — zeroed in place, a Nikon NEF stops decoding and a Canon CR2 loses its white balance, yet that is where the serials live, so RAW F1 blanks identity fields inside it, size-preserving, per maker, and needs two oracles (LibRaw sensor data AND camera-WB render). Full-size embedded previews carry their own metadata in 3 of 8 (DNG: GPS; RAF/RW2: serials). MAT2 supports none of the 8 formats; `exiftool -all=` leaves text serials in 5 of 8, leaves GPS inside the DNG's preview while listing none, and produced an undecodable RAF (one sample). **M16 (§10.1):** identity tables in `formats/raw/identity.py` (blank in place: Canon/Nikon/Olympus; remove note: Sony/Apple), decode-identical on 5 real files. **ExifTool is not the oracle for RAW either**: the Canon 80D keeps a 3rd owner-name copy in `CameraInfo` (0x000D) that ExifTool doesn't decode — removed by searching the maker note for every blanked text value, so residual checks must read bytes. **M17 (§10.2): RAW F1 registered as `raw`** (DNG/CR2/NEF/ARW/ORF; RW2 refused by name). Previews are KEPT and cleaned with `jpeg_f1.scrub(keep_icc=True)` + zero pad — decided by measurement (QuickLook thumbnail pixel-identical). Tag `0xC634` is DNGPrivateData in DNG but Sony's enciphered-WB pointer in ARW: remove in DNG only. **CR3 (M18, §10.4):** edit in place (CTBO holds absolute offsets); `CTMD` record 8 is a Canon maker note whose ColorData is LibRaw's CR3 white balance — never zero CTMD whole, edit per record. Canon `CameraInfo` (0x000D) is blanked whole (shot count / owner copy at per-body offsets), decode-safe on 80D + R6 III only. **RAF:** all identity is in the preview JPEG's EXIF, which LibRaw NEEDS (stripped → undecodable), so it is cleaned in place via `f1.clean_tiff` on a memoryview; the Fuji header block (0xC000) holds unnamed serial/date copies, removed by value search. All 8 surveyed RAW formats handled (M18 done). **M19:** RAW matrix published — A1@F1 pass in 5 maker-note layouts (same-length variants; length is limit #45), A2 stated not run (model kept by design; body needs a 2-body corpus), guard passes with 3 declared marks (blank zeros, preview EOI+pad, SOI+ICC).
- **Executables (P5 survey M0, `docs/p5_executables_plan.md`): acceptance is "runs the same"** (identical stdout/stderr/exit code), measured on hand-edited files before any code: ELF natively, PE under Wine 9.0, Mach-O on this Mac. **arm64 Mach-O: one changed byte → killed at launch (exit 137)**, so every edit recomputes the ad-hoc CodeDirectory page hashes ourselves — prototyped, runs identically, `codesign -v` accepts it, no Apple tool needed. Identity signatures (Developer ID, Authenticode) are refused, not stripped. Paths/commit stamps read BY the program (assert `__FILE__`, Rust panic paths, Go `.gopclntab`) are content: report, never edit. MAT2/ExifTool write no executable format; `strip` leaves build IDs that outlive the paths (ELF build-id is hashed from them; one-step `clang -g` UUID is random per build — deterministic Mach-O UUIDs do NOT encode paths, an early misreading corrected). Order: ELF → Mach-O → PE (ELF is the only one CI can build and run natively). **M1 (§8): ELF F1 built** (`formats/exe/`, id `exe`): unloaded sections zeroed by allowlist, build IDs recomputed (sha256 of cleaned bytes, IDs zeroed), Go stamp/pseudo-version/module path blanked only when `ReadBuildInfo` is not linked; loaded bytes checked unchanged on every scrub. 22/22 survey builds run identically; stripped builds of two users converge; limits #49–#51. **M2 (§9): Mach-O F1 built** (`exe/macho.py`, `exe/codesign.py`; Go rules shared in `exe/go.py`): unmapped segments (Go `__DWARF`) zeroed, path stabs blanked + N_OSO mtimes zeroed, LC_UUID/Go ID recomputed (hash excludes the signature), identifier → `a.out` (a `codesign -s -` identifier embeds the old UUID; universal builds name the SOURCE file), every code slot re-hashed. 20 real Mac programs run the same, `codesign -v` accepts all; two build dirs converge. CI has a macOS job. Linker never signs x86-64 slices. Limits #52 (identity signatures refused), #53 (≤4-char identifier kept). **Test ELF on x86-64 (`--platform linux/amd64`)**: gcc's CET `.note.gnu.property` is 8-aligned (broke M1 on CI). **M3 (§10): PE F1 built** (`exe/pe.py`): Windows MAPS debug sections, so the rule is "nothing refers to it" (no base reloc, no data directory) — `.reloc` is discardable too, never use discardable alone. Zeroed: link times, Rich header, DWARF, `.file` aux, version-resource identity strings (kept if `version.dll` imported); CodeView/MISC/REPRO debug entries removed (CET entry kept); checksum recomputed. Authenticode (#52) and .NET (#54) refused. 21 real PEs incl. pip's MSVC launchers (author's `C:\Users\` PDB path) clean; mingw/clang builds run identically under Wine. **M4 (§11): `exe` matrix published** (generated on x86-64 Linux — a Mac has one C compiler, so A2 reads not_tested there): A1@F1 pass in 12 layouts; A2@F1 FAIL by construction (code excluded from the channel; surviving container traits listed = F2 spec). Guard runs PER FAMILY (a mixed set can't fail on one format's mark) and `fingerprint_guard.explained()` now accepts runs made of declared marks + input-echoed pieces (cut at constants and min_len fill runs, strip fill at edges) — only ever excludes more.
- **Phase 6 M4 (§9.2): SVG F1 built** — XML surgery by resolved namespace (expat), embedded `data:` pictures scrubbed by their own handler via shared `src/scrub/embedded.py`, safety net = parsed event stream unchanged; 4,252/4,252 renderable app SVGs render identical (MAT2 changed 14/14). Guard: plugins may define `guard_view` (SVG blanks base64 payloads).
- **EXIF Orientation is content** (found in P6, `docs/p6_tail_plan.md` §9.1): all three JPEG tiers used to drop it, so portrait phone photos came out SIDEWAYS in every viewer (pixel tests can't see it — Pillow ignores the tag; test with `ImageOps.exif_transpose`). Now F1/F2 keep one canonical orientation-only APP1 (`jpeg/orientation.py`), F3 bakes the rotation into pixels (as MAT2 does). `exiftool -all=` has the same defect.
- **Phase 6 M3 (§8): GIF F1 built** — block allowlist (images, GCE, plain text, loop exts; ICC sanitized by the shared rule); comments, XMP, unknown apps, post-trailer bytes dropped.
- **Phase 6 M2 (§7): WebP F1 built** — RIFF rebuilt from an allowlist of image chunks (frames too), flags/size fixed, post-RIFF bytes dropped; A2 fails only on size across lossless encoders.
- **Phase 6 M1 (§6): plain TIFF F1 built** (`formats/tiff/`; `clean.py` is now shared with RAW). ICC: JPEG F1 DROPS ICC (sRGB assumption) — TIFF keeps it; published colour spaces (`icc.is_standard`, anchored description match) stay byte-identical, others sanitized. Truncated TIFFs refused (bounds check on for TIFF, off for RAW: real RW2 overstates its sensor data).
- **Phase 6 survey (M0, `docs/p6_tail_plan.md`)**: LibreOffice's SVG export embeds the original photo byte for byte (GPS, serial) and ExifTool reports no GPS for the SVG; MAT2 re-renders SVG and changed 14/14 app SVGs (emptied 2); Finder's *Compress* ZIPs carry each file's download URL, browser and quarantine ID in `__MACOSX/._*` sidecars (compressed), and MAT2 crashes on one holding a JPEG, leaving an empty `.cleaned.zip`; `exiftool -all=` leaves TIFF `DocumentName` (original path); Info-ZIP stamps the creator's uid/gid on every entry; MAT2 (Homebrew) fails WebP with exit 0. Decisions: TIFF in place via shared code from RAW; WebP/GIF block rebuild; SVG = XML surgery + embedded-image recursion + rsvg render check; ZIP rebuilt, sidecars/.DS_Store dropped, unknown members refused by default; EPUB = ZIP + OCF + OPF (author removed, ID derived); folder mode = one results sheet.
- **ZIP (P6 M5, `docs/p6_tail_plan.md` §10) is the first A2 pass at F1** — container channel only; members are scrubbed by their own handlers (`embedded.py`) and judged in their own matrices. Four archivers (Info-ZIP, Python, libarchive, `ditto`) → one output, byte for byte. Rebuilt through `ooxml/zipwrite.write_archive` (DOCX's `write()` output must stay byte-identical — check it when touching the writer): Unix create system, four modes (exec bit kept), UTF-8 bit 11 for non-ASCII names (Info-ZIP/ditto/libarchive write UTF-8 *without* it), folder entries only for empty folders. Sidecars dropped **by bytes, not names** (AppleDouble, `Bud1`, OLE). Plain text kept as content (limit #58); XMP files and unknown types refused unless `--keep-unknown-members`. MAT2 refuses a shell-script member and, kept, drops its exec bit.
- FLAC reaches **A2 at F2 losslessly** (E-FLAC: block size/framing/vendor separate producers at F1, collapse at F2, audio bit-identical via STREAMINFO MD5). FLAC + PNG are the free-A2 formats; JPEG/MP3 need a lossy tier because their fingerprint is inside the compressed content. FLAC F1 emits **no** padding and **no** empty Vorbis comment — both were tool constants the fingerprint guard caught; don't "normalize" a constant you can simply omit.
